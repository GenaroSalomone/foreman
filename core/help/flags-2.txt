    --no-report         deliberately launch fire-and-forget: no report channel is
                        resolved or provided; status still records and classifies it.
    --report-to <pane>  deliberately route reports to a live non-executor pane
                        other than this lane's brainer; recorded as chosen.
    --keep-pane [time]  retain the pane under a bounded lease for `hw next`
    --why <reason>      (default 4h, maximum 24h). Name who/what will re-task it.
                        Each proved done-invoker report creates one next-task authority.
                        A successful `hw next` consumes that authority; the next proved
                        report re-arms a fresh task-bound lease. Expiry closes the pane.
    --dry-run          print the dispatch, create nothing.
    --allow-stale-hooks launch even though the worktree's versioned hook settings
                       (.claude/settings*.json)
                       invoke a binary not on PATH — recorded in the receipt
    --fresh            build a fresh executor even when a reusable one is live
                       (contaminated context, another vendor/model, deliberate
                       concurrent work — recorded in the manifest)
    --no-reuse-check   legacy exact alias for --fresh

BRIEF KEYS (front-matter; docs/BRIEF-TEMPLATE.md lists the ones in use, this is the one owner of what each means)
    kind: build|explore|audit|review|design
                       what the task IS. A model the lane marks build-only is refused for
                       explore/audit/review. `design` + `asked: investigate` + `decision:`
                       is the consultant (fable, effort low); `design` + `asked: build`
                       meets the build ceiling (`top_tier_why:`). `build` silences the name
                       heuristic for a task like `fix-the-audit-script`.
    requested_by: "<who, date: the request, quoted>"  and  asked: investigate|build
                       what was asked for. hw refuses a dispatch without it where the lane
                       requires one and warns elsewhere; `investigate` does not implement.
    base: <branch>     the branch the worktree is built on; declare it on any task whose
                       result is measured. A check, never a source.
    agent: claude|pi   a check against the resolved vendor, like model:.
    sdd: none          accepted and ignored.
    requires: browser|subagents|repo|database  (comma-separated)
                       what the task NEEDS. hw warns, never refuses, when the target may
                       not have it: it knows the vendor, not what the session can reach.
    authorizes: <destination> :: <operation> :: <handle|none>
                       a remote operation the operator authorized, one entry per line (a `;`
                       does not separate entries). A Bitwarden item is not a handle: it goes
                       in `secrets:`.
    secrets: [<item>, …]  Bitwarden items (folder `agents`) the task needs, by name, never a
                       value; hw checks each is there before building. The executor reaches
                       one only as `hw secret run <item> --as VAR -- <cmd>`.
    placement: project-tab|legacy-space|here   worktree: new|none   database: own|main
                       the dispatch fields as checks (the flags still choose).
    invoker: <pane>    the brainer pane that must receive the report.
    review-skip: <why> with `review: none`: the one opt-out of a build's independent
                       review; the reason lands in the manifest.
    release: prod      a brief that writes prod data or deploys to prod. REQUIRES
                       env-from: and env-to: (app uuids), env-diff: {NAME: needed|not-needed}
                       (one ruling per name that differs, no more), screens: [<name>, …]
                       (done needs $HW_ARTIFACTS/screens/<name>.png newer than the run
                       start; sub-views are fine) and qa: <brief> (hw dispatches it with the
                       release; the close waits for it to report), and an `authorizes:` line
                       covering the read: the SSH host, each app's env list, printenv in each
                       backend container, both app uuids. hw diffs the two envs at dispatch
                       and again at close; a name ruled needed that still differs refuses
                       the close. Put the precheck that PRINTS the flags in Verification.
                       Dispatched, never `hw next`.
    rehearsal-of: <release brief>  (+ its own env-from:) refused unless that env matches the
                       release's env-to, or every difference is ruled not-needed there.
    model: <m>         a check against the resolved dispatch, refused before
                       anything is built on disagreement; never a source.
    effort: <level>    the same, for --effort: the same levels per vendor and
                       the same refusal words. A brief that declares neither
                       model: nor effort: gets one warning naming both.
    requires-agents: [primary:|subagent:]<name>[, …]
                       agents the task cannot do without. hw refuses the
                       dispatch when the executor cannot reach one from its
                       work directory, instead of warning.
    skills: [<name>, …]  skills the task needs: each must resolve for the executor
                       (worktree .claude/skills/<name>/SKILL.md, after replication, or the
                       account's user-level skills dir) or hw refuses the dispatch.
    review: judgment-day|plugins|none
                       the review, in every lane and --sdd mode. A build owes
                       the independent review for every value, absent too
                       (`hw review`; the builder runs no Judgment Day):
                       judgment-day has the reviewer run Judgment Day; plugins
                       and list items add the plugins: review skills to the
                       reviewer's tier; none opts out only with a review-skip:
                       line. Other kinds owe none: absent = no review. Another
                       value refuses the dispatch. `rdd` is retired: it warns
                       and runs judgment-day.
                       qa in the list: the reviewer runs the lane's qa-tester
                       once on its own dev server, the brief's Do and
                       Verification as cases, at 375 and 1440, captures in the
                       PR description's Review section; a failed case blocks.
                       The dispatch refuses qa in a lane with no qa-tester
                       (<checkout>/.claude/agents) or no devserver. A diff that
                       touches the lane's ui_paths (projects.json) gets qa added
                       to any review: list; only review: none turns it off.
                       A lane's review_default (projects.json) adds pieces to
                       every reviewer of its builds; to change one build's
                       review after dispatch, edit its brief's review: list
                       before `hw review`, never a ruling to the builder.
    plugins: [<name>, …]  installed review plugins (thermo, ponytail, pstack)
                       loaded into THIS executor only. They are an optional
                       install step, off by default (setup/vendor/plugins/install
                       or install.sh --with-review-plugins, into <brain>/plugins).
                       claude: one --plugin-dir each, hooks running natively in
                       that session (writes redirected to $HW_ARTIFACTS/plugin-state);
                       pi: one -e <plugin dir> each (skills and extension);
                       A name that is not installed refuses the dispatch before anything is built,
                       naming the command that installs them.
                       `webguide` (Chrome's modern web guidance) is guidance loaded at build time, not a
                       review piece: name it here on a brief that touches UI, never in `review:`.
    boundary: <what must never cross>
                       a build is not accepted as done without
                       $HW_ARTIFACTS/design-judgment.md naming it and ending
                       JUDGMENT: APPROVED (Judgment Day's design mode).
    decision: <what is undecided>   as --model-why.
    after: [<task>, …] the tasks of this lane the brief waits for. Before anything
                       is built hw checks each is reported (done-invoker) and
                       its branch is an ancestor of the base (a branch already
                       removed was merged); otherwise it refuses, naming which.
                       An unknown task refuses too. `--ignore-after --why` overrides.
